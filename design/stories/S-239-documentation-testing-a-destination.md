# S-239. Documentation: testing a Destination — the Test message, the step-by-step test and the accelerated run of the chains

## Scope

**IN**

- C-42.FR-12: a new page on testing a Destination, linked from the pages of the messengers and of outgoing webhooks,
  with screenshots.
- The documentation links of the panel's two parts, and the sentence about testing in the llms step list.

**OUT**

- The tests themselves: S-231 to S-238. The one-message test's own description in each messenger page, written for C-16
  by S-060 and S-104: this story links to the new page and leaves those sections.
- The API reference, which `make docs` renders from the spec.

## Contracts

- **Page**: `docs/concepts/testing-a-destination.md` with the sections "The Test message", "The step-by-step test"
  (anchor `#step-by-step`), "What each step sends", "Presses", "What a test never changes" and "Play the Escalation
  chains" (anchor `#play`), in the order of the acceptance statements; `mkdocs.yml` lists it in Concepts after
  `concepts/broken-destinations.md`. The pages of the messengers (`docs/messengers/mattermost.md`, `telegram.md`,
  `slack.md`, `bridge.md`) and of outgoing webhooks (`docs/outgoing-webhooks/events.md`, `templates.md`) get a link in
  their sections that describe the Test message; `docs/concepts/broken-destinations.md` links to it where it says a
  successful test ends the Broken state; `docs/llms.txt.tmpl` names the page in the step list for verifying a
  Destination,
  with a `quote` of one of its sentences, which the template check verifies against the page.
- **Documentation links** (`web/src/lib/docs-links.json`): `page.destination_test` →
  `concepts/testing-a-destination.md#step-by-step` and `field.chain_play` → `concepts/testing-a-destination.md#play`,
  used by "Learn more" beside the two parts in `destination-test-panel.tsx` through the existing `DocsLink`, with its
  test; `docslinkcheck` checks the entries against the built site.
- **Screenshots** (`web/e2e/screenshots/destination-test.spec.ts`, a new spec): a step of the run with its request and
  "Would mention:", and the timeline of the chains from a Saturday 03:00, in
  `docs/assets/screenshots/concepts/testing-a-destination/`; light theme as every documentation screenshot is
  (C-39.FR-7); generated, never listed.
- **Examples**: generic only (`infra-critical`, `payments`, the Team `devops`, `example.org`, "Phone gateway").
- **Settings cited**: `destination_test.idle_timeout`, `delivery.interactive_budget`.

## Notes

- Suggested commit: `docs: describe testing a destination with the step-by-step test and the accelerated run of the
  chains`.
- Implementation starts after the tag of 0.2.0: these capabilities ship in 0.2.x patch releases.

  (C-42.FR-9) and it is never described as a run of a chain.

  in the messenger, which Muster never does (lint 3).
