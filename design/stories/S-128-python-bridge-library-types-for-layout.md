# S-128. Types for the message layout in the Python bridge library (BE)

## Scope

**IN**

- The library's copy of `api/bridge.yaml` with `layout` (S-126), the generated models, their export from
  `muster_bridge`, and the README's example of reading `layout` (C-29.FR-8).

**OUT**

- Muster's side: S-126. The Go library: S-127. The guide on Muster's documentation site: S-130.

## Contracts

- **Repository** `muster-io/muster-bridge-python` (MIT, no CLA, ADR-0017), its AGENTS.md and Makefile; the pull request
  says `Part of muster-io/muster#<issue>` and `Story: S-128`, and the issue here is closed by hand once it merges.
- **Specification copy** (`api/bridge.yaml`): replaced by Muster's from `master`; `src/muster_bridge/models.py` is
  regenerated by datamodel-code-generator (never listed).
- **Package** (`src/muster_bridge/__init__.py`): re-exports the `Layout` models beside the other generated ones; no new
  call.
- **Tests**: `test_spec.py` validates a request and an answer with `layout` against the copy with openapi-core;
  `test_app.py` checks what the messenger receives; `test_layout.py` runs the README's example.

## Steps

1. Take the copy and regenerate. Check: `make spec-check generate-check`.
2. Export the models, write the tests and the README's example. Check: `make ci`.
3. Run the conformance check. Check: `make conformance`.

## Verification

In the repository: `make ci conformance` passes on every supported CPython; `python -c "import muster_bridge as m;
print(m.Layout.model_fields.keys())"` lists the fields of the acceptance. Against Muster: with `make dev` running from
Muster's `master`, `examples/memory_bridge.py` built from this branch receives `layout` in the envelope of a Root
message.
