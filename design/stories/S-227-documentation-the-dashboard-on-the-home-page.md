# S-227. Documentation: the dashboard on the Home page

## Scope

**IN**

- C-40.FR-12: the subsection of Statistics that describes the dashboard, with the screenshot of the Home page, and the
  documentation link of the dashboard.

**OUT**

- The dashboard itself: S-225, S-226. The views, the filters and the first acknowledgement of the statistics page:
  S-176, which this story extends and does not rewrite.
- The API reference, which `make docs` renders from the spec.

## Contracts

- **Page**: `docs/concepts/alert-groups.md`, a subsection `### The dashboard on the Home page` (anchor `#dashboard`)
  at the end of `## Statistics`, after "By people", written in the order of the acceptance statements. The navigation in
  `mkdocs.yml` is unchanged: the page exists.
- **Documentation links** (`web/src/lib/docs-links.json`): `page.dashboard` → `concepts/alert-groups.md#dashboard`; the
  dashboard section shows a "Learn more" beside its header through the existing `DocsLink` (`home-dashboard.tsx`, its
  test and the two locale files for the guide name "Dashboard" / «Дашборд» if `GUIDE_ABOUT` needs it); `docslinkcheck`
  checks the entry against the built site; `web/e2e/docs-links.spec.ts` presses it.
- **Screenshot** (`web/e2e/screenshots/alert-groups.clock.spec.ts`): the Home page after the data of the section is
  made with the development clock — Alert Groups acknowledged and resolved, a Page outside Working hours — taken in the
  light theme as every documentation screenshot is (C-39.FR-7); generated, never listed.
- **Examples**: generic only (`payments`, `KubePodCrashLooping`, `example.org`).
- **Settings cited**: `dashboard.refresh_interval`, `dashboard.noisy_alerts`, `retention.alert_group_summaries`.

## Steps

1. Write the subsection. Check: `make docs-serve`.
2. Add the link entry and the "Learn more", then the screenshot. Check: `make docs-screenshots GUIDES=alert-groups`.
3. Check the site and the component. Check: `make docs-check`, `make ci` (the component's test).

## Verification

1. `make docs-check` passes: pages, images and their alternative text, links, anchors and the anchors of
   `docs-links.json`.
2. `make docs-serve`, open Concepts → Alert Groups → Statistics → "The dashboard on the Home page": it reads in the
   order
   of the acceptance statements, with the screenshot.
3. `make dev`, open `/`, press "Learn more" beside "Dashboard": the page opens at that subsection.
4. Compare each sentence about a count with the page: "Calls" counts one per call however many Alert Groups it
   combined, as S-224's test shows.

## Open questions

None.

## Notes

- Suggested commit: `docs: describe the dashboard on the home page`.
- Implementation starts after the tag of 0.2.0: these capabilities ship in 0.2.x patch releases.
- The documentation sentence about "from when it counts" refers to the table's hint, which names the moment from the
  API (`outside_working_hours_since`, S-224), and gives no release number that the page would have to keep current.
- An Alert Group resolved together with its main one is left out of the statistics (C-37, S-206); the subsection says
  that the dashboard inherits it.
