# Architecture Decision Records

This directory records the architectural decisions behind Muster, a self-hosted alert grouping and on-call service that
sits after Alertmanager. Each record uses Michael Nygard's format — Context, Decision, Consequences — extended with an
Alternatives considered section, and carries a status and a date. Terms follow the glossary in
[`CONTEXT.md`](../../CONTEXT.md).

The records refer to Muster's layers: **L1** — the first release: grouping alerts into Alert Groups, acting on them in
messengers, delivery; **L2** — schedules, escalations, more sources and Connection modes, the Terraform provider;
**L3** — Incidents; **L4** — AI-assisted investigation.

Status values: Proposed, Accepted, Deprecated, Superseded by NNNN. A new decision gets a new file
`NNNN-<kebab-slug>.md`.

| ADR | Title | Status | Summary |
|---|---|---|---|
| [0001](0001-agpl-license-cla-and-dependency-policy.md) | AGPL-3.0-only with a CLA, and a dependency license policy | Accepted | AGPL-3.0-only plus a license-grant CLA via cla-assistant.io; strict license allowlist for shipped artifacts; any OSI license, plus CC-BY-4.0 for data-only packages, for tooling; no copied copyleft code. |
| [0002](0002-webhook-only-ingestion-with-snapshot-semantics.md) | Sit after Alertmanager; webhook-only ingestion with Snapshot semantics | Accepted | Alertmanager webhooks are Snapshots: Gone after two missing Snapshots at least 5 minutes apart (near-duplicates within 45 seconds count once), a resolved Alertmanager group resolves all its Alerts, Stale after 3× the interval learned per Alertmanager route, counting only time with a live Heartbeat; truncation tracked per `groupKey`; a new `startsAt` without `resolved` is a continuation while the Alert is open; ingestion never answers `400` and stores the body as received. |
| [0003](0003-route-first-then-group-by-label-list.md) | Route first, then group by a list of labels | Accepted | First-match Routes with a Default route; Alert Groups formed inside a Route by a Group key that is a list of labels; urgency from the Route or Severity level; Route edits never change a status. |
| [0004](0004-alert-group-state-machine.md) | Alert Group state machine | Accepted | Four statuses; Reopen restores the prior status; manual resolve with a Grace period; Quiet Unsnooze; new Alerts never remove an acknowledgement — only a rise in Severity level to Urgent and, where a Route turns it on, auto-unacknowledge after two unanswered Reminders do; no flapping, hold or maximum age in L1. |
| [0005](0005-delivery-as-desired-state-reconciliation.md) | Delivery as desired-state reconciliation | Accepted | One editable Root message per Alert Group and Destination, brought to the Desired state by the delivery worker with limiters per Destination and Connection; Loud events are always new messages; Storms per Route; a named interactive path for replies that takes limiter tokens first and fails fast; an exhausted retry budget makes the Destination Broken, and recovery sends only the current state; outgoing webhook events are ordered per Alert Group and delivered at least once. |
| [0006](0006-postgresql-only-storage-and-queues.md) | PostgreSQL as the only stateful dependency | Accepted | PostgreSQL 14 or newer; own thin mechanisms for ingestion, delivery and timers on `FOR UPDATE SKIP LOCKED`, `LISTEN/NOTIFY` and advisory locks; daily Stored Snapshot and monthly event partitions; no Redis, no queue library. |
| [0007](0007-active-replicas-with-advisory-lock-leader.md) | High availability: all replicas active, one Leader for singleton work | Accepted | Every replica serves and runs all workers, timers included; a session advisory lock with a bounded, pinged lease elects the Leader for the few singleton tasks; a session-capable DSN; one replica by default. |
| [0008](0008-spec-first-openapi-and-api-conventions.md) | Spec-first OpenAPI and API conventions | Accepted | OpenAPI 3.1.2 subset with oapi-codegen on the standard `ServeMux`; RFC 9457 errors, cursor pagination, ETag/If-Match, `public_id` in URLs, oasdiff gate from 1.0; one repeated `label=<matcher>` filter, omitted-keeps and null-clears on update, ingestion outside request validation, catalogued problem codes. |
| [0009](0009-spa-embedded-in-the-binary.md) | Single-page UI embedded in the binary | Accepted | React SPA built into the Go binary with `go:embed`; TanStack, shadcn/ui on Base UI, orval-generated client, SSE hints for live updates. |
| [0010](0010-configuration-only-through-the-api.md) | Configuration only through the API | Accepted | The database is the only source of configuration, changed through the API; environment only for bootstrap, all `MUSTER_*`, with the database as a URL or as fields and the session connection defaulting to the main one; no provisioning; mandatory master keys never generated by Muster; first admin from env; `--actor` for state-changing CLI commands. |
| [0011](0011-application-level-secret-encryption.md) | Application-level encryption of secrets with a keyring | Accepted | AES-256-GCM with key ids; a Keyring from `MUSTER_SECRET_KEYS` with the active key chosen in the database; activation only when every replica holds the key; a random Signing secret per outgoing webhook Destination; a key canary at startup, re-encrypted on activation. |
| [0012](0012-template-sandbox.md) | Template sandbox | Accepted | One Go template sandbox for messages, Link rules and outgoing webhooks, with explicitly registered sprout functions and Alertmanager function names; loop and output caps; dry run on save; Fallback template for messages at runtime; a failing outgoing webhook template leaves that delivery Not delivered. |
| [0013](0013-account-links-from-web-session-only.md) | Account links only from a signed-in web session | Accepted | Telegram `/start` token or Mattermost DM code, both started from the Muster profile; no links from chat, no email matching; Mattermost via REST API and a bot account. |
| [0014](0014-metrics-and-logging-policy.md) | Observability: metric labels, histograms, Internal alerts, an outgoing heartbeat and a closed log catalogue | Accepted | Entity labels by immutable id plus `*_info`, never alert labels or users; `le` histograms only; pull-only `/metrics`; Leader-only DB gauges; Internal alerts and log events as closed registries in code, one name per condition for Internal alerts and chart rules; an outgoing heartbeat from the Leader to an external dead man's switch. |
| [0015](0015-outbound-http-and-ssrf-policy.md) | Outbound HTTP and SSRF policy | Accepted | One outbound client package; no redirects; retry policies by client class; standard or strict outbound address policy checked after name resolution, loopback blocked unless allowed, metadata and link-local always blocked, the proxy's own address checked too; per-client proxies configured in the UI; a Telegram Bot API base URL checked by a dry probe, the token sent only to the saved address and redacted from logs and errors. |
| [0016](0016-flat-domain-packages-command-layer-and-architecture-lints.md) | Flat domain packages, a command layer and architecture lints | Accepted | Flat `internal/<domain>` packages and flat CRUD; one dispatcher for the Alert Group lifecycle; CI lints for Organization filtering, write paths, messenger calls, outbound HTTP, secrets, contexts, logging and histograms. |
